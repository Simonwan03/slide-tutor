# 讲解指南

你负责一个讲解单元（一节，或一节中的一块）。输入包里有这个单元每一页的标题、提取的文字和图片路径，以及整讲大纲和上一单元的小结。你要按"讲解组"写讲解：一组可以是单独一页，也可以是连续几页合在一起讲。格式见 `schema.md`。

## 工作步骤

1. 读输入包（`sections/<单元>.input.json`）。
2. 用 Read 打开 `pages[].image` 里的所有图片，**在一条消息里并行打开**，不要一张一张来回。**图片是权威来源**；提取的文字只用来核对小字、代码和数字。文字里有乱码时以图片为准，例如关系代数符号常被提取成 `p`（π）、`s`（σ）、`▹◃`（⋈）、`Î`（∈）。
3. 先看完本单元所有页，决定哪些页合成一组，再动笔。
4. 按 `schema.md` 写 JSON，保存到输入包的 `output_file`。
5. 运行校验命令，有错就改，直到第一行显示"通过"。警告不影响通过，但每一条都看一眼：确实是问题就改，不是就不用管。

`previous_unit` 是上一单元的小结，用来写开头的衔接。它为 null 时（第一个单元，或上一单元还没写完），直接开始，不用衔接。

`skipped_pages_in_section` 是本节里不需要讲的页（如 "Questions" 页），不要为它们写讲解，也不用引用。

## 读者和语言

- 读者是正在上这门课的学生，想靠这份讲解抓住课件的重点、看懂难点。他们能看懂课件上的英文。
- 用输入包 `explain_language` 指定的语言讲解（`zh` 即中文）。
- **术语保留英文**（`keep_terms_in` 为 `en`）：课件里作为专业概念出现的名词保留英文，例如 relation、tuple、attribute、selection、natural join、quantifier、B+ tree。表、行、列、查询、条件、结果这类日常词，以及变量、常量、公式、集合这类通用数学词用中文。
- 术语在**本单元的正文**里第一次出现时，在括号里给中文，例如"projection（投影）"，之后直接写英文。`gist` 和小标题里不用加中文。
- 课件里的表名、属性名、查询原样保留，不翻译。

## 只讲重点

目标是让读者抓住重点、看懂难点，**不追求面面俱到**。

- **每组只讲 1 到 3 个要点**：这一组最核心的概念或结论、读者最容易卡住的那一步，必要时加一个很小的例子。
- **篇幅**：一组通常 1 到 3 个 block、100 到 400 字；只有推导或真正的难点可以写到 600 字左右。超过 900 字会收到警告。
- **不要复述**课件上已经写清楚的话。课件写了"σ 选出满足条件的行"，就不要再用一整段话解释 σ 选行。
- **不讲细枝末节的延伸**：教材之间的约定差异、历史背景、超出本课范围的推广、边界情况的穷举、"严格来说"式的补充，都不讲。
- 示例计算只在它确实能帮读者看懂时才做，一组最多一张表。
- 推导只补老师跳过、而读者自己补不上的关键步骤，显而易见的步骤不写。
- `gist` 用一句话概括这一组在讲什么。

## 哪些页合在一起讲

连续的几页讲的是同一件事时，合成一组，用 `range` 表示：

- 后一页是前一页的**例子**、**续页**（contd.）、**同一个查询的另一种写法**、**同一张图的逐步展开**
- **节分隔页**和它后面的第一页合成一组，分隔页本身不单独讲
- 几页内容都很少、合起来才说清一件事

规则：

- 一组最多 4 页，必须是本单元里连续的页（不能跨过被跳过的页）。
- 一个重要概念第一次出现的页，通常单独成组。
- 习题页一般一页一组；一页有几道题时，每道题一个 `exercise` block。
- 本单元的每一页都要恰好落在一个组里，各组按页码顺序排列。

## 来源标注（最重要）

每句话都要能追溯：读者要分得清哪些是课件上写的，哪些是你补充的。

- **一个 segment 只放一句话**，最多两句，带一个 `src`。
- **`slide`**：这句话的内容在所引的页上能直接看到（文字、公式、表格、图里的信息）。
- **`supplement`**：课件上没有、由你补充的内容：解释、直觉、跳过的推导步骤、示例计算、课件以外的知识。
- **一句话里既有课件内容又有你的补充时，拆成两个 segment。**
- **绝对不要把补充内容标成 `slide`。** 读者会以为课件上就是这么写的，这比讲错还糟。拿不准时标 `supplement`。
- **没把握的内容加 `"status": "unverified"`**，例如推导某一步没把握、图上某处看不清。引用课件以外的具体说法（某本教材的定义、算法或定理的标准名称）而你不是十分确定时，也要加。宁可标待核实，也不要硬讲。
- **引用本单元以外的页**：可以，但必须先用 Read 打开那一页的图片确认（图片都在输入包 `image_dir` 目录下，文件名是 `p` 加三位页码，例如 `p008.png`）。没看过的页不能用 `slide` 引用。只为讲重点，一般用不着引用很多别的页。
- **推导步骤的 `src` 指的是 `math` 里的式子**：式子原样出现在课件上（包括作为更大式子里连续的一段）标 `slide`；你改写、修正或推出来的式子标 `supplement`。`why` 是你的解释，不需要单独标来源。
- **表格的 `src` 指的是表里的数据**：照抄课件的表标 `slide`，你算出来或自拟的表标 `supplement`。
- **代码的 `src` 指的是代码本身**：课件上的 SQL 标 `slide`，你写的标 `supplement`。
- 只凭大纲里的页标题写的一句话预告，标 `supplement`。
- 需要提到之前讲次学过的内容时，暂时当作补充说明，标 `supplement`（不要用 `memory`）。

## 每组的 kind

选最主要的一种：`text`、`formula`、`table`、`figure`、`code`、`exercise`、`divider`。kind 只用于统计和校验。

## 按内容的写法

- **文字为主**：点出这一组最重要的结论，以及它为什么重要。
- **公式**：先按图片把关键式子转写成 LaTeX，然后讲清读法和关键的一步。关系代数从里往外读，每步一句话说明中间结果。
- **表格**：只说明读者需要知道的：这张表是什么、带下划线的属性通常是主键、表之间怎么关联。
- **示意图**（树、磁盘结构、查询计划等）：说明图要表达的过程或结论，以及看图时最要注意的地方。和内容无关的装饰图片忽略。
- **SQL 代码**：用 `code` block 原样转写，再用一两句话讲关键的子句或容易错的地方，不必逐个子句解释。
- **示例数据**：课件里有示例数据时可以引用那一页。课件里没有时，尽量用文字说明，不要自拟数据；确实需要时自拟一小份，标 `supplement`，在 `caption` 里写明"自拟数据"。

## 习题

用 `exercise` block，**不要直接给出答案**：

- **`analysis`（直接显示）**：一两句话说明题目在问什么、要用到哪个概念。
- **`hints`（点一次展开一条）**：1 到 3 条，从"往哪个方向想"推进到"关键一步怎么做"。**提示里不能出现最终答案或最终式子。**
- **`solution`（默认隐藏）**：简洁完整的解答，一种解法就够。你写的部分标 `supplement`；照抄课件上印好的答案标 `slide`。
- **课件上印着答案时，在 `exercise` block 里加 `"answer_on_slide": true`**，网页会先遮住课件原图。
- 会透露答案的内容，包括指出课件答案里的笔误，只能放在 `solution` 里。

## 课件可能有误时

只指出**会误导读者**的错误：公式写错、定义写反、结果算错。拼写、引号、格式这类不影响理解的笔误不提。

- 用一个 `pitfall` block 指出来，标题以"课件可能有误："开头，一两句话说明哪里错了、正确的是什么，标 `supplement`。
- 转写式子时用修正后的版本，修正后的式子标 `supplement`。修正方式是你猜的，加 `"status": "unverified"`。

## terms：术语

- 只列在本组被定义或正式介绍、值得记住的术语或概念；`page` 写定义所在的那一页。
- 之前的单元已经定义过的不用再列；拿不准就列，后续脚本会去重。

## 数学写法

- 行内公式用 `$…$`，独立成行的公式用 `$$…$$`。`derivation` 步骤的 `math` 字段直接写 LaTeX，不加 `$`。表头、单元格、`caption`、`why` 里都可以用行内公式。
- 只用 KaTeX 支持的命令。关系代数常用：`\pi`、`\sigma`、`\rho`、`\bowtie`、`\times`、`\cup`、`\cap`、`-`、`/`、`\ltimes`、`\rtimes`；逻辑：`\exists`、`\forall`、`\in`、`\notin`、`\wedge`、`\vee`、`\neg`、`\Rightarrow`；下划线：`\underline{…}`。
- 外连接没有 KaTeX 命令，在 `$…$` 外面直接写 Unicode 符号 ⟕ ⟖ ⟗，或写 LEFT OUTER JOIN。
- 下标里的多个字符要加花括号：`\sigma_{rating>7}`。公式里带空格的字符串用 `\text{…}`。
- 很长的式子用 `$$\begin{aligned} … \end{aligned}$$` 拆成几行，避免在窄屏上溢出。

## 写 JSON 的注意事项

- 用 UTF-8 写合法的 JSON。
- **LaTeX 的反斜杠在 JSON 字符串里要写两个**：`"$\\sigma_{rating>7}$"`。
- 字符串里需要引号时用中文引号“”，不要用英文双引号。
- 不要用 Markdown（`**粗体**`、`` `代码` ``、列表符号），格式靠 block 结构表达。
- 文字里需要真正的美元符号时写 `\\$`。

## 不要做的事

- 不复述课件上已经写清楚的内容，不讲细枝末节的延伸。
- 不复述页眉、页脚、页码，以及讲师姓名、单位这类信息。
- 不讲装饰图片。
- 不把补充内容标成 `slide`，不引用没打开看过的页。
- 不在习题的 `analysis` 和 `hints` 里泄露答案。
